# ADR 012: Дизайн-система и визуальный язык

**Статус:** ПРИНЯТО
**Дата:** 2026-08-12
**Владение:** styles.css, tailwind.config.js, ui-kit.tsx, все `*.ui.tsx`

## 1. Решение

Единственный источник визуальной истины — токены. Tailwind-тема расширяется
из существующих CSS-переменных `--app-*`, компоненты потребляют только
именованные утилиты; произвольные значения (`text-[NNpx]`, `rounded-[NNpx]`,
raw hex, `z-[NN]`) запрещаются grep-гейтами. Тёмная тема — переназначение
значений токенов, а не `!important`-переопределения перечисленных классов.

Шкалы:

- **Радиусы:** `control` 12px, `card` 18px, `sheet` 24px — и только они.
- **Типографика:** caption 11 / body-sm 13 / body 15 / title 17 / display 24.
  Минимум 11px; uppercase-кириллица меньше 11px запрещена.
- **Z-шкала:** именованные уровни `nav < fab < sheet < modal < toast <
  critical` (константа `Z` в коде, без magic numbers).
- **Нижняя геометрия:** одна формула
  `--app-bottom-clearance = --bottom-nav-height + зазор + --app-safe-bottom`;
  от неё считаются и padding-bottom экрана, и позиции FAB/пилюль/CTA.
  Компоненты не используют raw `env(safe-area-inset-*)` — только
  `--app-safe-*`.

## 2. Контекст и ограничения

Токены объявлены в `styles.css`, но adoption ≈ 0: карточки живут на пяти
радиусах, текст — на девяти произвольных кеглях, z-index — magic numbers
38–80. FAB и save-pill (до 124px от низа) перекрывают контент при резерве
92px; CHECK-пилюля с `pointer-events:auto` глотает тапы; shopping-CTA на raw
`env()` наезжает на nav в Telegram WebView; тёмная тема покрывает только
перечисленный список классов — всё вне списка (тёмные карточки счетов,
чёрный баланс магазина, цветные чипы) не адаптируется. В ui-kit нет
Button/Input/Select/Badge/EmptyState; один и тот же инпут-рецепт скопирован
8 раз; Modal и NotesSheet — две независимые sheet-реализации; native
`confirm()/alert()` в 9 местах.

Ограничение: миграция экранов выполняется дешёвыми моделями, поэтому каждый
шаг обязан быть механически проверяемым (grep-инварианты, snapshot-тесты
примитивов), а логика (hooks, store, queries, api) при миграции неприкосновенна.

## 3. Целевая архитектура

Слои (порядок внедрения жёсткий):

1. **Токены** — `tailwind.config.js` (`colors.app-*`, `borderRadius.control|card|sheet`,
   `fontSize` шкала) поверх `var(--app-*)`; `--app-bottom-clearance` в
   `styles.css`; константа `Z`.
2. **Примитивы** — `ui-kit.tsx`: `Button` (primary/secondary/ghost/danger,
   min-h 44px), `Input`/`Textarea`/`Select`, `Badge`, `EmptyState`, единый
   `Sheet` (поглощает Modal и NotesSheet), `ConfirmSheet`; snapshot-тесты
   классов каждого примитива.
3. **Геометрия** — фикс наложений: все плавающие элементы и паддинги от
   `--app-bottom-clearance`; kanban без `100vw`-математики.
4. **Миграция экранов** — по одному тикету на экран, только JSX/className.
5. **Темы** — удалить `!important`-блок; тёмные значения токенов через
   `[data-telegram-theme]`; `theme-color` в `index.html` = токен акцента.
6. **Диалоги/обратная связь** — `confirmAction()` (Telegram `showPopup` либо
   `ConfirmSheet`); тосты стеком до 3.

Definition of Done экрана: 0 произвольных значений вне шкал; обе темы на
360/390/672px без наложений при полном скролле; все строки пользователя с
политикой переполнения (`truncate`/`line-clamp`); тап-таргеты ≥ 44px с
aria-label на icon-only кнопках.

Нумерация волн — `docs/backlog/README.md` и карта волн в ADR 013 §3.

## 7. Риски и митигации

- Дешёвые модели «творят» при миграции → секции «Не трогать» в тикетах +
  grep-инварианты в AC + diff-запрет на store/queries/api.
- Регресс существующих ui-тестов → они входят в AC каждого тикета
  (`npm run check`).
- Telegram themeParams меняют палитру в рантайме → тёмные значения задаются
  переназначением токенов, покрыты ручным чеклистом обеих тем.

## 8. Отклонено / отложено

- **Отклонено:** редизайн с нуля / смена стека стилей (Tailwind остаётся);
  Playwright-скриншот-тесты (Telegram WebView им недоступен, ручной чеклист
  дешевле и достаточен); фронтовый роутер (таб-навигация сохраняется).
- **Отложено:** анимации/микровзаимодействия сверх существующих; кастомная
  иконографика; светлая/тёмная тема вне Telegram themeParams.

## 9. Критерии приёмки

1. Grep-гейты §6 зелёные по всем `*.ui.tsx` и `ui-kit.tsx`.
2. Обе темы на 360/390/672px: ни одного наложения, ни одного проглоченного
   тапа (FAB, save-pill, CTA, nav).
3. Card-радиус один по всему приложению; кегли только из шкалы.
4. Native confirm/alert отсутствуют; тосты стекуются.
5. `npm run check` зелёный после каждого тикета волны.
